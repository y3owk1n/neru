# Linux backends — native-boundary contracts

Read `../AGENTS.md` first (slots, factory, stubs, generated `wlr_protocol/`). This file covers what it omits. These rules are scattered across file-head comments; violating them fails at link or run time, not compile time.

- **Backend selection is runtime, not build-tag**: KDE and wlroots are identical at compile time (`linux && wayland`); dispatch on `platform.DetectLinuxBackend`, never add a compositor build tag.
- **Every cgo symbol has a `_nocgo.go` twin** returning `derrors.CodeNotSupported` ("requires CGO-enabled Linux builds"); pinned by `system_stub_contract_test.go` — a supported capability must never answer `CodeNotSupported` or return nil. The exceptions, on both backends, are the queries that worked and found nothing: `FocusedApplicationPID` reports `CodeNotSupported` when no window is focused, and again when the window that is focused publishes no pid (`_NET_WM_PID` is a convention EWMH does not require), so callers degrade instead of surfacing a live desktop as a failure. Each wears its own sentinel — `errNoFocusedWindow`, `errNoWindowPID` — because `neru doctor` explains them in different words, and a failure must wear neither. They are not gaps, and the capability is live-probed rather than declared, so the guardrail sees the two move together.
- **The `.c` files compile in exactly one unit** (`cgo.go`). Packages that call bridge symbols must blank-import `platform/linux` — and `wlr_protocol` separately — or the linker fails with undefined symbols.
- **Xlib protocol errors go through the one shared trap** (`x11_error_trap.h`), never a second `XSetErrorHandler`. The default handler calls `exit()`, so any request that can legitimately fail — reading pixels off a drawable that shrank, reading a property off a window whose client just died — has to be trapped; and the handler is process-global, so two traps under two mutexes would interleave and leave one caller's requests running under the handler that exits. Keep trapped sections short: everything else that traps waits behind them.
- **`doc.go` is tagged `linux`, not `linux && cgo` — deliberately.** The `.c` files already gate cgo builds; the broader tag keeps analysis working on other hosts. Don't "fix" it.
- **C→Go signaling is fd-based** (self-pipe from a native thread); there are zero `//export` callbacks here by design. The monitor owns its fd: treat it read-only, never close it; monitors run for the daemon's lifetime.
- **Never block on the eventtap goroutine.** Mid-action native calls (e.g. libei lazy connect) run on the goroutine holding the keyboard grab — a slow call freezes global hotkeys. Timeouts stay short; session establishment belongs to warm-up.
- **Never dial the session bus directly from this package.** `dbus.ConnectSessionBus` / `dbus.SessionBus` take no context — connect, auth handshake and Hello are all uncancellable — so every dial here goes through `sessionBusDialer` (`session_bus_dial.go`), as does the app's theme observer, which reaches it through exported `ConnectSessionBus`. The caller chooses two things: `refuseWhileDialing` (the input path, which holds the keyboard grab) versus `awaitTheDialInFlight`, and whether the connection is `processWide` — a private one no caller is left waiting for is closed, and the `dbus.SessionBus` one never is, because the tray speaks over it too. `TestSessionBusDialer_Dial_RefusesASecondCallerWhileOneIsStuck` and `TestSessionBusDialer_Dial_LeavesTheProcessWideConnectionOpenWhenAbandoned` pin those two. Whether a dialer may be *shared between callers* follows from the first: `awaitTheDialInFlight` hands every waiter the same connection, so a shared one may only carry that policy where the connection is nobody's to close (the notifier's is `processWide`). A caller that closes what it gets either shares a `refuseWhileDialing` dialer, as the portal does, or builds one per call, as `ConnectSessionBus` does — `TestPrivateBusConnection_GivesConcurrentCallersConnectionsOfTheirOwn` pins the second. What a wedged bus is *reported* as belongs to each caller and never to the dialer — three callers, three sets of words, all unchanged by the extraction.
- **Capability probes**: one capped goroutine per probe, never restarted while wedged — native calls can't be canceled, and probes are reached from long-lived IPC handlers. Per-feature isolation is pinned by `capability_probes_test.go`.
- **uinput/evdev**: writes to the device fd must be contiguous (never interleave with a concurrent feed); releasing our modifier must not clear one the user physically holds. On Wayland the keyboard is a proxy (`eventtap/linux/evdev_proxy_cgo.go`, ADR 0014): every physical keyboard is held for the daemon's lifetime and re-emitted through `neru-keyboard-proxy`, one goroutine writes to it, and the one invariant is that a release is re-emitted exactly when its press was (`forwardRule`, pinned by `TestForwardRule_AReleaseGoesWhereItsPressWent`). Never grab a device that reports touch or pen position axes (`hasPointerAxes`; its touches would have nowhere to go, while a volume knob on ABS_VOLUME is no reason to refuse a keyboard) and never grab a `neru-` device (the proxy would read its own output). A grabbed keyboard that reports relative axes, a remapper's output device typically, has its motion and mouse buttons re-emitted on `neru-pointer-proxy`, created on first need; buttons and motion bypass the forward rule (`isPointerButton`, `isMouseButton`). A remapper's auto-detect grabs `neru-keyboard-proxy` and closes a loop, so the proxy probes its own nodes for another process's grab and fails open (`probeOwnDevices`); the probe runs only on the run goroutine, because that goroutine is the proxy's sole writer and nothing can be emitted inside the probe's grab. A remapper's output device arriving, or found by the initial scan, yields every physical keyboard to it (`yieldPhysicalKeyboards`), each let go only once idle so a forwarded press keeps its release, and taken back after the remapper's grab window if unclaimed.
- **XTest is the exception to that last clause, and only for pointer injection.** An X11 button event carries the server's live modifier state instead of a set the sender chooses, so presenting `--modifier` means the keyboard actually holding it — and presenting *no* modifier means releasing one the user is. Every pointer path — scroll, click and drag — therefore suppresses a physically-held modifier for the length of an injection (`neru_ax_query_keymap` / `neru_ax_key_event`; the decision is `platform/modifierstate`, which is pure Go and tested). Pressing it back is the risky half, not the release: a modifier left released while the user holds it drops out of everything they do next, so restore is unconditional apart from a key that reads down again. A drag is the one hold that outlives its call: mouse-down stashes the plan (`modifierstate.Stash`) and mouse-up replays the restore half on a fresh connection, which is sound because a keycode names a key on the server rather than on the connection that read it — never reach for holding the `*C.Display` open across the drag instead.
- **Every modifier key that hold injects is announced to the event tap first.** X11 has no way to tag a key event as ours, so an injected press re-enters the keyboard grab as the user's, and a press plus a release *is* a modifier tap — with `sticky_modifiers.enabled` that latched one nobody pressed (#1484). The tap's suppression bookkeeping is fed through `tap.SyntheticModifierSink`, a Tier 3 extension declared beside the `Tap` contract and wired into the injection backend by the app (`app/wiring_platform_linux.go`); the injection path has one call site for a key event (`x11ModifierHold.inject`) so that announcing cannot drift from injecting. One announcement is one key event — `TestEventTap_RememberSyntheticModifier_RegistersOneNamePerKeyEvent` pins that, because a second one nothing answers sits out the suppression window and swallows a modifier the user really pressed. Wayland needs none of it — `zwp_virtual_keyboard_v1_modifiers` generates no evdev or `wl_keyboard` event — and Windows needs none either, because `SendInput` carries the tag on the event that X11 lacks.
- Naming: `neru_<subsystem>_*` snake_case, one `.c`/`.h` pair per subsystem, `#cgo pkg-config` on the consuming Go file.
