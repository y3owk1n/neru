# Overlay adapters — contracts

These rules fail silently at runtime, not at compile time; read before editing.

- **Threading is platform-asymmetric.** macOS serializes through the Obj-C bridge (`dispatch_async` to the main thread); Linux must serialize itself — Cairo/X11/Wayland calls are not thread-safe (`linux/manager.go`).
- **A draw may block, and must never be called while the mode handler's lock is held.** Draws dispatch asynchronously on macOS but hold `renderMu` synchronously on Linux; that asymmetry is deliberate, so callers must assume the blocking case. The mode handler computes what to draw under its lock and draws after releasing it (`internal/app/modes/AGENTS.md`); the exceptions are the whole hints surface — the update callback (`hintdraw.go`), the theme refresh and the search input, which now go through the port but still draw under the handler lock, and whose first draw per activation runs the entire `ShowFrame` transition (resize, show, switch) under it — and mode teardown, which hides indicators and clears the frame under it. `h.mu` → `renderMu` is therefore a real edge, and safe only while the reverse never exists: nothing holding `renderMu` may call into the app layer or publish to a subscriber that takes `h.mu`.
- **Lock topology is deliberate.** The manager owns `renderMu`, held across synchronous draws; animation goroutines lock it via `sharedOverlay`. The mouse-action indicator owns an independent X11/Wayland connection and must **not** share `renderMu` — it has its own `indicatorMu` / `indicatorRenderMu`.
- **Surface primitives split** (#1177): layout, animation, offsets, and label logic live once on `sharedOverlay`; only buffer management, HiDPI scale, and window lifecycle go behind `overlaySurface`. Shared code never touches cgo — primitives take Go types and own their C marshaling, including CString lifetimes.
- **Backend exported methods are thin nil-guarded delegates** — a promoted method through a nil backend pointer panics before any receiver guard runs. `Get()` must never return a typed nil, or every `!= nil` guard downstream silently passes (`backend_linux.go`).
- **`originOffset` applies selectively**: grid, recursive-grid, and hints arrive screen-local and get the offset — including the virtual pointer, which rides the recursive-grid frame. Absolute draws (the cursor-tracking mode and sticky-modifiers indicators, monitor_select, click indicator) must not.
- **The overlay owns the Styles it hands out** (#1207): `StyleResolver` (`style.go`) is the only place the *drawn* styles — hints, hint search input, grid, recursive grid, monitor-select, virtual pointer — are built from `config + theme`. It resolves on a config reload or a theme change, never per draw, and `Apply` is also the one notification that hands a new configuration to the render components — one call to `ConfigureComponents`, because the manager knows which components it built. Read one via `overlay.ResolvedStyle(source)`; a `BuildStyle` call anywhere else re-creates the fan-out this replaced, and a missed call site leaves an overlay in the previous theme's colours. **Still outside it**: the mode-indicator, sticky-indicator and virtual-pointer overlays hold their own `ThemeProvider` (handed to them at construction) and resolve their colours at draw time, and the click indicator's style is built in `app/services/action_service.go`.
- **The overlay builds its own render components** (#1209): `Base.BuildComponents` (`manager/components.go`) constructs them from a `ComponentSpec` — configuration, theme provider, logger, window handle, headless verdict — and keeps them; the app hands over the first two and gets the built set back for the few call sites that still talk to a render component directly (the frame port, #1210 and #1211, removes those). The window handle and the headless verdict come from the backend's own `BuildComponents`, which is the only reason that delegate exists: a `Base` cannot see the surface, and a `Base` method cannot dispatch to a backend's override (darwin's `UseVirtualPointerOverlay` propagates screen-share state, so darwin re-applies it after the build). A backend delegate must nil-guard its receiver like every other exported method here. A failed component is logged and left nil; only the virtual pointer fails the build, because that is the one the app's startup phase treated as fatal.
- **An Indicator is driven through the port, never through its render object** (#1208): `ShowIndicator` / `HideIndicator` / `ResizeIndicatorToActiveScreen` take a `ports.Indicator`; `manager.Base` resolves it to a render component and answers "never constructed" itself, so no caller nil-checks one. `HideIndicator` owns clearing as well as hiding — on macOS the component has its own window, on Linux it is a badge painted on the shared surface and hiding it means erasing that rectangle (`linux/manager.go` overrides it for exactly that). The app side is one service per indicator in `app/services/{modeindicator,stickyindicator,virtualpointer}`, all built on `app/services/indicator`.
- **A mode hands over a Frame; this package owns the sequence that realises it** (#1210): `Adapter.ShowFrame` (`adapter.go`) is the only place `ResizeToActiveScreen` → `Show` → `SwitchTo` → draw exists, and `ClearFrame` the only place the leaving half does. `RedrawFrame` draws a frame already on screen and deliberately skips the window sequence — hint labels narrow on every keystroke, and a `Show` per keystroke is a `dispatch_async` of window level, collection behaviour and ordering that ADR 0003 rules out. A `ports.Frame` carries domain values only: converting them to render models and meeting them with the resolved Style happens here and nowhere upstream, and `internal/architecture/overlay_frame_test.go` fails the build if a Frame field is typed from anything but the standard library or `internal/domain/`. Hints is converted; grid, recursive grid and monitor-select still draw through the manager (#1211, #1212).
- **The hint search input's geometry is resolved here too** (#1210): `SearchInputLayout` travels with the Style, so a config reload moves the box and a draw does no configuration lookup; `searchInputFrame` places it against the screen the caller names and clamps it on. `HintSearchBounds` exists because the platform IME field has to sit over the same rectangle — asking beats deriving it a second time in the mode layer.
- **Layering exception**: app code may import this package for vocabulary and render models only (`layering_test.go` `sharedInfraPackages`); behavior still goes through `ports.OverlayPort`. `render/*` owns style and drawing only — state and math live in `internal/domain/*` or `app/services/*`. Optional backend capabilities are reached by type assertion, not interface widening.
